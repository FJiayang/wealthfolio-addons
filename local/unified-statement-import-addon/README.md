# 账单导入

本地插件，适用于 Wealthfolio
3.12.0 及以上。支持支付宝、微信、银行及记账平台账单，不属于官方插件目录。全部解析和账目处理在本机完成，无网络权限。网页导出缺少订单号时只能预览，不能提交。

## 0.4.4 支持格式

| 渠道 | 导出结构 |
| --- | --- |
| 支付宝 | 交易明细、网页查询、电子客户回单 CSV |
| 微信 | CSV / XLSX（含长单号、尾空列、退款及中性流水） |
| 招商银行 | 借记表格／PDF、信用卡年月对账单 |
| 浦发、中信 | 交易流水号／顺序号借记明细；记账金额／结算金额信用卡 |
| 工商银行 | 借记 v1/v2、借记 PDF、信用卡；按实际表头选择列 |
| 建设、中国、农业、交通、广发、兴业银行 | 对应借记／信用卡结构；广发仅接现成转换 CSV，不解析 PDF |
| 民生、微众 | 民生借记 PDF／信用卡 CSV；微众借记 PDF |\n| 汇丰香港、BMO、TD | 汇丰借记／信用卡 CSV、BMO 借记／信用卡 CSV、TD 无表头 CSV |\n| 中国银行 PDF | 借记流水、按币种分区的信用卡明细 |\n| 京东、美团、随手记 | 支付账单、App／网页分表／随手云；随手记按关联 ID提示配对 |

表格读取在本机完成，SheetJS CE 0.20.3 随 ZIP 打包；银行及记账平台的 XLS/XLSX 与同构 CSV共用渠道列映射。格式兼容性目前以合成样本及参考源码为依据，不宣称已覆盖每家机构所有导出版本。

P0–P4 已接入多文件、工作表选择、四态行、来源账户隔离、映射升级、表单规则、原始统计对账、真实单边转账与手续费组成部分恢复。基金申赎已并入统一导入；证券专用格式仍不在本版范围。账单不能证明身份或金额精度时，需补全稳定来源账户、重新导出或明确跳过，不提供随机编号强制入账。

Architecture impact：修改统一导入插件及工作区依赖锁文件，移除独立基金插件。基金由内存草稿交接改为复用宿主校验后统一保存。解析和校验仍在本地执行，保留宿主账户、活动、事件、分类、备份及同步边界；新增持久化只包括映射 v2、用户规则和 metadata v1 可选字段。保存继续使用 `saveMany`，普通单边转账另用 `getTransferPair/linkTransfer` 确认与关联；投资资金双边使用共享 sourceGroupId 同批创建；消费关联通过当前宿主的同一次 `saveMany` 事务提交新增和更新；不增加后台任务、自动重试、新数据库或网络权限。

## 开发和安装

在 `wealthfolio-addons` 根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm --filter unified-statement-import-addon test
pnpm --filter unified-statement-import-addon type-check
pnpm --filter unified-statement-import-addon bundle
pnpm --filter unified-statement-import-addon test:package
```

在 Wealthfolio 插件设置中选择“从文件安装”，安装
`local/unified-statement-import-addon/dist/unified-statement-import-addon-0.4.4.zip`，授权读取账户、读取活动、批量保存及转账查询／关联。从活动页“支出 → 添加活动”打开“账单导入”（移动端从导入按钮选择）。要求宿主支持 `spending-import` 清单位置；不再提供侧边栏入口，旧版宿主会忽略此入口。开发服务：`pnpm --filter unified-statement-import-addon dev:server`。

## 使用

1. 选择渠道（导出变体留空时自动识别），逐个添加 CSV/XLS/XLSX/PDF。TD 无表头文件须明确选择渠道；BMO、TD 等缺少币种的文件须先选择账单币种。密码 PDF 在上传页填写密码，错误后可重新读取，密码仅在本次会话内使用。PDF 预览可从来源页码定位原页。可选择工作表、移除单个文件，原始预览保留实际行号。缺少银行来源账户时填写稳定标识并重新解析；目标账户不用于生成来源身份。CSV 支持 UTF-8、GB18030 及带 BOM 的 UTF-16，按表头识别逗号／制表符／分号。源声明统计差异只提示，不丢弃明细。
2. 按付款方式名称匹配并核对目标账户。唯一高置信账户自动预填；多个高置信候选须人工选择。界面显示选择来源、候选及匹配理由，无论是否有候选，都可从宿主返回的全部账户中选择。插件不按账户类型、币种、持仓模式或活跃/归档状态过滤账户。点击“保存映射并预览”才保存映射，不保存原文件。账户已不存在时须重新选择，支持重置。
3. 映射页将未完成项置顶，补齐账户及记账性质，或选中分组后在顶部跳过。审核表格支持筛选、列固定／隐藏／调整宽度、键盘编辑和可编辑字段粘贴。交易关闭自动排除且不可恢复；“不计收支”默认跳过个人记账，明确退款成功仍按退款识别。默认跳过可通过顶部操作恢复，恢复后须补齐性质、金额和账户；异常交易状态须选中记录，在顶部“标记已核对”。现金转账、充值、提现和还款默认跳过，恢复后必须确认转入／转出、实际账户及金额，不允许改成普通收支绕过转账确认。投资识别默认关闭；需要导入基金时须在上传前开启。所有错误及待核对记录必须修改、核对或跳过后才能提交；修改异常状态记录的金额、性质或账户后须重新核对。
4. 确认后保存，普通收支完整成功后自动进入“查看收支”；含转账或消费关联时保留结果页以继续核对。跳转失败可在结果页重试“查看收支”，不会重新提交账目。再次上传相同订单自动标为重复，现有账目不会覆盖。部分保存或结果不明确时保留结果页，先“刷新核对”，再决定是否提交剩余记录。

请先在主项目支出设置中开启支出跟踪并纳入目标账户；插件不会修改跟踪范围。支付宝原始分类写入备注，例如“支付宝分类：餐饮美食”，同时保留商户、商品说明、原备注和订单号。可在系统分类规则中添加“包含 支付宝分类：餐饮美食”的规则，限制流水类型为支出（WITHDRAWAL），选择系统餐饮类别；具体商户规则可设置更高优先级。退款应按系统支持的退款类型另设规则。

保存后的自动分类由宿主现有后台流程完成，插件不调用分类识别或类别赋值接口。刚进入收支页可能短暂显示未分类；没有匹配规则时保持未分类。原始分类为空时不添加分类片段，旧账目备注不回填、不覆盖。

记账性质直接读取“收/支”列，收入和支出无需再次选择。交易状态精确匹配 `交易成功`、`支付成功`、`代付成功`、`解冻成功`、`芝麻免押下单成功`，仅去除首尾空白；`退款成功`保留独立退款识别，`交易关闭`排除。其他状态（包括新出现的“xx成功”）保留已知性质并要求人工核对。组合支付、红包、优惠等付款方式不再单独触发核对，仍须选择实际资金账户。

未知性质按渠道和原始收支值分组，空值单独归组；一次选择或跳过作用于组内尚未处理的流水，不覆盖逐行修改。分组仅用于当前导入，不保存额外规则，也不合并账目。异常状态按渠道、原始状态和核对原因分组。两类分组默认展开全部关联明细，显示来源行、时间、商户、商品说明、原始收支、识别性质、金额、付款方式和交易状态。映射页分别显示待补齐类型数、流水笔数及异常状态待核对数量。

审核页以行号旁的警告图标和黄色单元格提示核实项，错误使用红色。双击“记账性质”“确认金额”或“目标账户”可直接编辑，也可选中单元格后按 F2／Enter。核实后勾选行首复选框，再从顶部批量“标记已核对”；修改后重新核对，校验错误不能借此放行。

余额宝等持仓模式账户可以正常匹配和选择，不应为了导入映射到无关银行卡。花呗等负债消费仍须核对实际资金账户，本版不管理分期计划，信用卡还款仅记录实际现金转账。插件不按账户类型阻止收入、支出或退款，交易合法性由宿主保存接口校验。无论所选账户的基础币种是什么，账单金额和活动币种保持原始币种，不按目标账户币种擅自换算。

## 基金与投资资金流水

投资识别使用主项目同款开关，默认关闭。未开启时，投资交易及资金流水的处理状态会引导返回上传步骤，勾选“识别投资交易流水”后重新读取文件。

上传文件前勾选“识别投资交易流水”，本次有文件后不能切换；结束导入后恢复默认关闭。支持原蚂蚁基金 12 列文字型 PDF，以及带订单号的标准基金 CSV（date、symbol、quantity、activityType、unitPrice、currency、fee、amount、comment，tax/subtype/account 可选）。CSV 备注中的“订单号：”或“Ant Fund order:”用于稳定识别；同订单的转换双边按基金代码和买卖方向区分。其他券商格式不保证兼容。

银行或支付渠道的投资关键词仅用于提示疑似投资用途；申购、赎回、买卖可建议转账，收益、分红、利息和费用等须选择处理方式。映射页先匹配账单资金账户，再以可折叠表格展示上传页的全部预览字段及账户流向；原始内容完整显示，可滚动查看。用户可批量填充投资账户，并展开例外记录单独调整。方向、金额、账户或处理方式变化后须重新核对。投资账户的选择仅保留在本次导入中。每笔确认的资金流水生成银行卡/钱包与投资账户之间的内部转账；基金文件只生成投资账户内的 BUY、SELL 或分红再投资，不补造银行流水。投资账户须使用与流水相同币种、按交易流水跟踪的证券账户；基金明细要求人民币。资金账户保留原流水币种，不按账户基础币种换算。

有投资明细时，在账户映射后进入资产识别：沿用宿主表格单元格编辑，支持修正确认日期、代码、金额、份额、费用和净值，搜索选择资产，或明确标为手动资产后校验。净值留空时复用原基金算法计算。特殊转换可补充另一侧并修正；信息不足时必须补齐或跳过。资产识别通过宿主 checkImport/searchTicker，可能调用已启用的行情源；关闭投资识别时不会调用。

匹配要求投资账户、币种、最终金额、资金方向和用途一致且双方候选唯一。申请日期优先；只有确认日期时，申购允许扣款后 7 个自然日内确认，赎回允许确认后 7 个自然日内到账。订单号中的日期不作为权威申请时间。不同销售机构、转换、分红再投资、金额不一致及多候选不会自动关联；不进行合计凑额。

银行和支付导出若描述同一笔资金事件，满足同账户、同金额、同机构及五分钟/日期同日条件时追加来源凭据，只保留一组转账。投资交易与资金关联独立于普通消费归零关联，不会把基金买卖金额归零。

支持银行先导、基金先导或同批导入。找不到另一侧时可先导入并保留待关联，先导基金时资金侧暂未补齐。审核页及“已保存投资资金与买卖关联”提供人工候选确认和取消关联；取消只移除业务关联，保留转账及买卖，保存取消选择防止自动重连。

兼容独立基金插件的旧备注和订单号。基金文件能够完整核对原活动时只认领来源，不重新创建或覆盖经济字段；只有银行文件时，旧活动须人工确认关联。已有金额、日期、账户、份额、费用或资产发生修改时不会自动关联。

原独立蚂蚁基金插件已从仓库移除。升级统一插件后应停用旧安装的基金插件；卸载插件不会删除已经保存的交易。投资入口和收支入口均打开统一向导，投资识别开关都默认关闭。

## 账户自动推断

付款方式、账户名和账号先做 NFKC、小写转换，分离括号尾号、末尾独立四位数字或掩码尾号；完整数字账号取末四位。随后去除空白和符号，按名称相等、双向前缀或包含关系召回候选。不会将名称中任意数字作为卡号。

插件内维护常见境内银行别名表，将名称开头的全称和简称统一，例如“中国农业银行／农行”对应“农业银行”、“招行”对应“招商银行”。按最长别名优先匹配一次，保留卡种、用途和尾号。两字简称后仅允许为空或明确卡种描述，避免把“平安保险”“中信证券”等误识别为银行；候选理由显示别名匹配依据。

从宿主返回的全部账户中按名称相等、双向前缀或包含关系召回候选，不推断或限制账户类型。尾号用于辅助区分同名账户，明确的尾号冲突不推荐，但账户仍可手动选择；仅尾号相同、名称不匹配时不召回。账户名和账号自身尾号不一致时不自动预填。

尾号一致加100分。名称信号只取最高项：完全一致80分；账户名是付款方式前缀40分加长度（最多20）；反向前缀20分加长度（最多10）；仅包含10分。高置信须满足名称匹配且尾号一致、非泛化名称完全一致，或长度至少4的非泛化账户名前缀。“信用卡、银行卡、余额、账户余额”等泛化名称不能单凭名称达到高置信。分数只决定候选顺序，多个高置信候选不按分差自动选择。

逐行人工选择优先于保存映射，保存映射优先于用户规则，用户规则优先于推断。恢复映射和提交前核对仅要求目标账户仍在宿主返回的列表中，不额外过滤账户。清空或重置后，本次会话不会立即自动填回；新上传可以重新推断。账户自动映射不解除异常交易状态的核对要求；未知性质仍需分组补齐，审核页的逐行人工修改优先保留。

## 语言与显示格式

插件名称、描述、菜单及自身界面固定使用简体中文，不注册翻译，不随宿主语言切换。

日期时间、金额和计数复用宿主格式化接口，分别跟随显示区域、时区及各原始币种的区域设置。金额编辑支持相应小数点、分组符和数字字符；提交时仍使用精确的英文小数点字符串。原始时间可在日期单元格提示中查看，来源 metadata 和去重依据不会因语言或区域切换而改变。

## 来源与扩展

新增记录的 `metadata.unifiedStatementImport` 使用
`{version: 1, sources: [...], booking: {...}}`。来源包含
`system`、`recordId`、商家订单号、账户提示、文件名、物理行号、原始时间及上海时区转换后的时间、原金额、币种、支付方式、状态、收支方向、分类、商户、商品和备注。`booking`
保存确认后的性质、金额和目标账户，原来源不随人工改金额变化。

按 `system + recordId`
查重，覆盖所有可读取账户；同一订单的经济内容或商户明细变化会报冲突。不同文件名、行号或目标账户选择不会绕过重复检测。缺少订单号不可提交。备注附订单号，避免核心将同日同额不同订单误判为重复。

新增同构 CSV 渠道需要实现 `StatementParser`、在 `src/parsers/index.ts` 注册并补充中文提示。解析器描述渠道名称、支持格式、上传提示、账户映射说明和来源编号标签；异步 `parseStatement()` 返回渠道、变体、文件、工作表、来源行和统计信息，页面和记账层从注册表读取渠道信息。

读取层支持 CSV、XLS/XLSX、文字型 PDF，Excel 预览是单元格表格，不执行 HTML 或公式。无法保证精度的数值单元格阻断该行。来源 metadata 继续读写 v1，新增可选的变体、来源账户、工作表、余额、对方账号、日期精度、费用、PDF 起始页码及原始行字段。银行身份按渠道、来源账户和流水号／确定性复合身份隔离；同文件复合身份碰撞须补证或跳过。映射 v2 按渠道、来源账户和归一化付款方式存储；旧键仅供支付宝迁移，先保存新配置，再删除已迁完的旧键。

消费关联保留两条活动，不合并来源：银行记录实际扣款，支付宝、微信、京东或美团记录记账金额为零，原始金额保留在来源中。自动关联仅用于银行卡直接支付的普通消费，同金额、同币种、同实际账户且双方候选唯一；时间精确时相差不超过五分钟，只有日期时限同一账单日。多候选只提示；钱包、退款、转账、投资和手续费不自动归零。

metadata v1 新增可选 `association: {peerSourceKey, role, originalAmount}` 和 `cancelledAssociations`，使用稳定来源身份连接双方，不借用宿主转账接口。支持任意导入顺序和已有插件流水；历史金额、账户、币种或日期与导入时不一致时，不自动修改。审核页可取消本次关联；“已关联记录”允许取消已保存关联，恢复三方关联前金额，保留后续人工金额修改，并记录取消选择避免下次重连。主项目不显示自定义关联入口，需在本插件管理。来源及关联存于活动 metadata，无独立流水数据库。

## 规则、转账和手续费

招商借记账单中的普通“转账／汇款”按金额正负记为收入或支出，不仅凭摘要推断本人账户间划转；需要时可手动改为转入／转出并确认。投资资金仍受投资识别开关控制。

招商 PDF 按相邻日期行的中点划分流水区域，保留日期上方和下方的跨行摘要、对手名称。缺少首页标题时可按完整招商表头识别，缺少账号时仍须补填稳定的来源账户标识。此次修正可能改变旧版复合流水编号；旧版已导入账单再次导入前须核对已有记录，插件不自动迁移历史活动。

映射页提供规则表单，支持启停、优先级、渠道和来源账户范围、字段包含／等于、全部／任一条件、金额区间及上海时间段（含跨午夜）。逗号分隔多个关键词。高优先级覆盖低优先级，同级后者覆盖；忽略命中后默认跳过，用户可恢复。不预置启用任何跨渠道忽略规则，规则结果不会自动冻结为保存映射。规则只选择已有实际资金账户，不创建账户或修改宿主分类。

有手续费的来源须确认主流水实际金额、手续费金额及扣费账户，再分别创建主流水和 `FEE`。不会自动假定账单金额是否含费用。metadata booking 用 `main/fee` 区分组成部分，旧记录默认 main；部分成功后只补缺失部分。结果分别显示来源行数和新增活动数。

转账只创建账单实际存在且用户明确确认的一侧，不虚构对手。已保存转账面板从宿主读取真实配对状态，允许用户选定两条流水后关联；兴业购结汇的同账号、同摘要、不同币种、三分钟窗口及随手记关联 ID只用于候选预选，仍须确认。状态读取或关联失败时显示待核对，重试前重读宿主，不重复创建流水。已链接其他转账的记录不可抢占。关联会由宿主更新两条活动的分组和内外部标记，其他账目字段不覆盖。

尚未实现且不属本版范围：跨渠道消费合并与来源追加、退款原单关联、分期、扫描件 OCR、EML 邮件解析、券商专用格式、在线模板及多窗口并发唯一约束。账户号缺失且无法补证，或原文件已丢失数字精度时，不能靠人工点击“已核对”放行。

## 限制

- 插件的预览不是核心导入向导的 `checkImport`；提交仍经过核心 `saveMany`
  校验。不产生 CSV 导入运行历史。
- 插件将分类写入备注及来源信息，不创建或直接赋予系统类别；类别由宿主已有规则异步识别，或由用户人工归类。
- 消费关联只调整符合条件的插件流水记账金额及关联 metadata，保留原始来源、账户和备注。转账关联会经用户确认调用宿主接口更新分组；不补建对手流水，不管理借款计划、分期或组合支付拆分。
- 源身份不受数据库唯一约束保护。仅支持同一插件串行导入，不支持多窗口并发提交；其他入口导入的无插件来源数据无法可靠查重。
- SDK 活动查询不返回归档账户的账目。相关账户须先取消归档，才能检测其中的来源重复；隐藏但未归档账户仍参与检测。
- 源信息属于账目 metadata，包含账单明细，随主程序原有备份与同步边界处理。插件本地存储只保存账户映射与用户规则；原文件和密码不持久化，取消关联选择写入对应活动 metadata。
- 不兼容或损坏的插件来源 metadata 会阻止提交；不静默忽略后重复入账。

## 验证与样本保护

`test` 使用合成账单，不包含真实样本。内部单元测试覆盖渠道、PDF 重建、密码错误、页面状态、关联金额与时间边界、历史人工修改、取消幂等及响应丢失恢复。

`docs/demo/` 已加入 Git 忽略规则，真实文件和派生数据不得复制进源码、夹具、快照或安装包。本地真实样本测试只读目录中的 PDF／CSV，使用模拟 SDK 验证预览、提交请求及重复导入，不写入真实账本：

```sh
pnpm --filter unified-statement-import-addon test:demo
```

招商 PDF 的日期、币种、金额、余额和笔数与本机 Poppler 的独立文字提取交叉核对；运行本地真实测试需要 `pdftotext`。worktree 可用 `STATEMENT_DEMO_DIRECTORY` 指向原样本目录，不复制样本。不将真实样本预期值写入版本控制。未提供真实样本的银行格式以参考源码和合成测试验收。浏览器验收使用 `test:browser` 在临时数据库中验证真实保存、基金资产识别、跨次匹配和取消关联。

单独验证含朝朝宝转出流水的本地招商 PDF，可设置 `STATEMENT_CMB_PDF` 为文件绝对路径后运行 `pnpm --filter unified-statement-import-addon exec vitest run src/demo.test.ts`；测试只读取原文件并在模拟账本中校验双边方向。
