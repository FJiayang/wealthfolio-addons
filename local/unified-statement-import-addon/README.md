# 账单导入

本地插件，适用于 Wealthfolio
3.11.0 及以上。首版支持支付宝交易明细 CSV，不属于官方插件目录。全部解析和账目处理在本机完成，无网络权限。

## 开发和安装

在 `wealthfolio-addons` 根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm --filter unified-statement-import-addon test
pnpm --filter unified-statement-import-addon type-check
pnpm --filter unified-statement-import-addon bundle
pnpm --filter unified-statement-import-addon test:package
```

在 Wealthfolio 插件设置中选择“从文件安装”，安装
`local/unified-statement-import-addon/dist/unified-statement-import-addon-0.1.2.zip`，授权读取账户、读取活动和批量保存。从活动页“支出 → 添加活动”打开“账单导入”（移动端从导入按钮选择）。要求宿主支持 `spending-import` 清单位置；不再提供侧边栏入口，旧版宿主会忽略此入口。开发服务：`pnpm --filter unified-statement-import-addon dev:server`。

## 使用

1. 上传支付宝交易明细 CSV（UTF-8 或 GB18030）；自动定位表头，忽略说明区汇总数字。
2. 按付款方式名称匹配并核对目标账户。唯一高置信账户自动预填；多个高置信候选须人工选择。界面显示选择来源、候选及匹配理由，无论是否有候选，都可从宿主返回的全部账户中选择。插件不按账户类型、币种、持仓模式或活跃/归档状态过滤账户。点击“保存映射并预览”才保存映射，不保存原文件。账户已不存在时须重新选择，支持重置。
3. 核对预览。交易关闭自动排除；不计收支、组合支付及未知状态需确认性质、实际金额和账户。理财、转账和还款本版不处理，请排除。未确认行不会提交，支持仅提交已就绪部分。
4. 确认后保存。再次上传相同订单自动标为重复，现有账目不会覆盖。结果不明确时先“刷新核对”，再决定是否提交剩余记录。

余额宝等持仓模式账户可以正常匹配和选择，不应为了导入映射到无关银行卡。花呗等负债消费仍须核对实际资金账户，本版不管理分期或还款。插件不按账户类型阻止收入、支出或退款，交易合法性由宿主保存接口校验。无论所选账户的基础币种是什么，账单金额和活动币种保持原始 CNY，不在插件内换汇。

## 账户自动推断

付款方式、账户名和账号先做 NFKC、小写转换，分离括号尾号、末尾独立四位数字或掩码尾号；完整数字账号取末四位。随后去除空白和符号，按名称相等、双向前缀或包含关系召回候选。不会将名称中任意数字作为卡号。

从宿主返回的全部账户中按名称相等、双向前缀或包含关系召回候选，不推断或限制账户类型。尾号用于辅助区分同名账户，明确的尾号冲突不推荐，但账户仍可手动选择；仅尾号相同、名称不匹配时不召回。账户名和账号自身尾号不一致时不自动预填。

尾号一致加100分。名称信号只取最高项：完全一致80分；账户名是付款方式前缀40分加长度（最多20）；反向前缀20分加长度（最多10）；仅包含10分。高置信须满足名称匹配且尾号一致、非泛化名称完全一致，或长度至少4的非泛化账户名前缀。“信用卡、银行卡、余额、账户余额”等泛化名称不能单凭名称达到高置信。分数只决定候选顺序，多个高置信候选不按分差自动选择。

逐行人工选择优先于保存映射，保存映射优先于推断。恢复映射和提交前核对仅要求目标账户仍在宿主返回的列表中，不额外过滤账户。清空或重置后，本次会话不会立即自动填回；新上传可以重新推断。自动映射不等于已确认交易性质，不解除未知状态、组合支付等记录的逐笔复核要求。

## 语言与显示格式

插件名称、描述、菜单及自身界面固定使用简体中文，不注册翻译，不随宿主语言切换。

日期时间、金额和计数复用宿主格式化接口，分别跟随显示区域、时区及 CNY 单币种区域设置。金额编辑支持相应小数点、分组符和数字字符；提交时仍使用精确的英文小数点字符串。原始时间可在日期单元格提示中查看，来源 metadata 和去重依据不会因语言或区域切换而改变。

## 来源与扩展

新增记录的 `metadata.unifiedStatementImport` 使用
`{version: 1, sources: [...], booking: {...}}`。来源包含
`system`、`recordId`、商家订单号、账户提示、文件名、物理行号、原始时间及上海时区转换后的时间、原金额、币种、支付方式、状态、收支方向、分类、商户、商品和备注。`booking`
保存确认后的性质、金额和目标账户，原来源不随人工改金额变化。

按 `system + recordId`
查重，覆盖所有可读取账户；同一订单的经济内容或商户明细变化会报冲突。不同文件名、行号或目标账户选择不会绕过重复检测。缺少订单号不可提交。备注附订单号，避免核心将同日同额不同订单误判为重复。

新增同构 CSV 渠道需要实现 `StatementParser`、在 `src/parsers/index.ts` 注册并补充中文提示。解析器描述渠道名称、支持格式、上传提示、账户映射说明和来源编号标签；`parseStatement()` 返回 `{parserId, rows}`，页面和记账层从注册表读取渠道信息。

当前读取层仍只处理 CSV；新增 xlsx/PDF 需要另行适配读取层，不能仅注册解析器。来源 metadata 继续读写 v1，未知版本仍明确报错，不提前引入 v2 或未使用的标准字段。映射查找集中在 `resolveAccount()`，存储继续使用原始付款方式键；接入多个渠道或来源账户时须升级为带渠道及来源账户身份的键并处理旧映射。

`sources[]` 仅是来源存储结构，**不代表已实现跨源关联或去重**。本版只按同源订单号查重，不会吸收银行卡或信用卡账单行。来源存于系统账目，无单独插件流水数据库或浏览器 localStorage。

### 后续扩展验收门槛（本次未实现）

1. 取得真实渠道的脱敏样本后确定格式和稳定来源身份，再按实际需要增加账户标识、入账日期、参考号或 xlsx reader。
2. 跨源先实现候选预览和来源追加。只有相同已映射账户、币种、金额、方向及渠道明确可比的参考号精确一致且唯一时，才允许自动关联；日期与金额相近只能人工确认，保留用户改过的记账字段。
3. 转账和还款复用宿主配对能力，但现有转账 API 不能原子保存插件来源，必须先验证分步写入和失败恢复，不能直接视为已解决幂等问题。
4. 真实跨源流程验证后，再扩展多文件会话、退款关联、多币种与分期。若仅修改插件不足以安全完成来源追加或恢复，先说明限制并调整范围，不新增插件账本绕过宿主限制。

## 限制

- 插件的预览不是核心导入向导的 `checkImport`；提交仍经过核心 `saveMany`
  校验。不产生 CSV 导入运行历史。
- 分类仅作为来源信息保存，不自动创建或赋予系统分类。
- 不修改既有活动，不创建内部转账、借款计划或分期，不处理组合支付拆分。
- 源身份不受数据库唯一约束保护。仅支持同一插件串行导入，不支持多窗口并发提交；其他入口导入的无插件来源数据无法可靠查重。
- SDK 活动查询不返回归档账户的账目。相关账户须先取消归档，才能检测其中的来源重复；隐藏但未归档账户仍参与检测。
- 源信息属于账目 metadata，包含账单明细，随主程序原有备份与同步边界处理。插件本地存储只保存账户映射。
- 不兼容或损坏的插件来源 metadata 会阻止提交；不静默忽略后重复入账。

## 验证

`test` 使用虚构商户和订单，不包含用户原始账单。可只读检查真实 DEMO：

```sh
STATEMENT_DEMO_PATH='/绝对路径/支付宝交易明细(20250101-20251231)_DEMO.csv' pnpm --filter unified-statement-import-addon test
```

该验收检查 52 条明细（支出 26、收入 4、不计收支 22，交易关闭 2）。默认提交测试使用模拟宿主；安装后的真实保存仅在隔离测试环境中验证，不应用真实账户试导入。

另有可选的真实后端测试：`STATEMENT_TEST_ORIGIN=http://127.0.0.1:端口 pnpm --filter unified-statement-import-addon exec vitest run src/import/host.test.ts`。必须使用全新隔离的数据目录，仅有一个名为“账单隔离测试账户”的 CNY 现金账户且无活动；测试会写入三笔虚构活动并验证再次提交不新增。测试不自动清空数据库，也不得指向日常使用环境。

## 共享导入界面（0.1.1）

要求 Wealthfolio fork
v3.11.0.14+。使用 addons 仓库 `packages/import-wizard-ui` 的向导组合组件，底层控件、DataGrid 和主题变量复用宿主 `@wealthfolio/ui`。流程为上传、账户映射、核对、提交确认、结果；只有确认提交后才写入 ready 行。错误、待确认、重复和排除行不会提交。

### 0.1.3 界面收敛

共享源码由 Vite 打进插件 ZIP，不增加宿主模块桥接或业务 API。状态统计使用宿主语义配色；逐笔预览改用 56px 行高容纳 32px 下拉控件，长文本保留完整内容提示。来源 metadata、账户映射和提交核对流程不变。

配套撤销宿主共享向导 UI 导出时，必须先升级到本版；旧版插件无法在移除导出的宿主上运行。

来源 metadata、账户映射、提交前重新读取核对和未知结果恢复仍由插件负责。完整成功、部分完成和结果待核对分别展示；本次新增数只使用保存响应确认的数量，不把刷新后出现的重复计作成功。本次仍仅支持支付宝 CSV，不包含跨来源合并。

取消及移除文件前确认；移动端离开保护沿用宿主边界，不拦截浏览器历史或提供刷新恢复。本地开发链接同级
`wealthfolio`
仓库的 SDK/UI/React；先构建宿主两个共享包，再执行本插件的 type-check、test、bundle 和 test:package。

Architecture impact：0.1.2 移除插件的账户过滤和收入账户类型限制，持仓模式及其他类型账户可按名称匹配和手动选择；宿主 API、网络权限、同步边界和 `getAll/saveMany` 创建路径不变。metadata 仍写入 v1，不新增数据库、后台任务或重试机制。提交前重新核对账户是否仍存在，变化导致预览不同则停止写入。测试覆盖推断、全部账户选择、持仓模式余额宝导入、手工优先级、账户消失阻止提交及重复导入；真实跨源和还款尚未实现或验证。
